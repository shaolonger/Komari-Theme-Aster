# 网络报告 v3：从升级到定时报告

本指南对应主题 **1.8.0**、插件 **1.7.0**、runner **1.7.0**。支持 Komari **≥1.4.3**；使用独立 HTTPS worker，不要求修改 Komari 或 komari-agent，不依赖 Web SSH。目标是实例详情中的「路由 / 测速 / 国际」成组报告。

## 一、升级三个部分

1. 从 GitHub Release 下载 `Komari-Theme-Aster-v1.8.0.zip` 和 `Aster-Network-Observatory-v1.7.0.zip`，分别更新主题和插件。插件允许 API 路由与读取节点清单的系统 RPC。已有探测器密钥不会自动重置。
2. 每台执行检测的 VPS 运行下面的一键命令。它自动识别受支持的 Linux 包管理器、安装缺失依赖、校验发布 ZIP/NextTrace/TcpQuality 文件，安装 systemd 服务，然后进入凭证向导。

   ```sh
   curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh | sudo sh
   ```

3. 向导填写面板 URL、**节点 UUID**、网络观测探测器密钥。UUID 来自 Komari 节点信息，不是 komari-agent token。已有相同面板/UUID 的配置可回车保留旧密钥。没有密钥时，在实例详情 → 网络检测 → 管理探测器生成一次性凭证。
4. 确认服务在线且实例页显示 `runner 1.7.0`。只升级面板不会升级 VPS。若新配置覆盖旧安装，重新执行此命令会保留现有凭证；向导核实连接后启动服务。

支持 systemd 的 Debian/Ubuntu、RHEL 系 dnf/yum、openSUSE zypper；NextTrace 支持已校验的 amd64、arm64、armv7、riscv64。容器、非 systemd 或其他系统并不冒称一键支持。软件更新依赖联网访问 GitHub 与系统软件源。

## 二、先获得无需大陆设备的报告

1. 打开某台 VPS 的 **实例详情 → 网络检测 → 定时计划**。主页「批量配置网络检测」也使用同一个编辑器。
2. 第一步选 **国际基础**（少量目标）或 **国际完整**。完整预设包含 34 个 AWS STS 区域、48 个网站/API/CDN 目标、五个 Telegram IPv4 启动地址；IPv6 可切换并选择对应地址。IDC 基础预设选择部分地区，完整目录有 42 个 xTom/Leaseweb 接入目标。
3. 第二步设定各模块独立周期。国际默认 30 分钟；每天定时可填写 `04:00, 21:00` 等最多八个时刻，并选择 IANA 时区。界面显示下次执行；重复时刻去重。
4. 第三步选择当前 VPS、多台 VPS 或分组，按需启用分组继承。点击 **预览每台 VPS 的覆盖与累计容量**，检查原因后保存。
5. 返回「国际」点击立即检测。每个目标十块代表**本轮十次 TCP 握手**；主数值是成功样本中位数。红色是失败，灰色是未采样。点卡片查看 IP、逐次耗时、失败原因与独立 HTTPS 响应。

AWS 指标是区域 STS 接入延迟；网站/CDN 可能命中附近接入点，不代表地区全网延迟。Telegram 使用官方桌面客户端地址快照，TCP 通不代表 MTProto 登录或解锁。401/403 是应用响应，不能认定网络不通。新采集器固定本轮解析的公网 IP；私网/CGNAT/保留代理地址不作为国际实测。

## 三、路由：回程、去程与 BGP 分开理解

1. 选择 **大陆线路** 预设，默认包含北京、上海、广州的三网 IPv4 路由目标；完整目录有 47 个 NextTrace 公布目标。切换 IPv6 后须勾选 IPv6 目标，不会静默替换地址。
2. 可同时选 TCP 443 / ICMP，分别保存。页面按方向、地区、运营商和协议切换，保留 Last/Avg/Best/Worst、发送/响应数、探测未响应比例、IP/ASN 和原始 MTR。
3. 公共去程使用 Globalping 的实际大陆 ASN 覆盖。可用目录、额度、失败与实际测量来源会记录；它不是承诺北京/上海/广州固定九个测量点。没有覆盖会收尾为缺测，不能从回程推算去程。
4. 需要固定来源时，在 **测量资源 → 登记大陆测量点** 一次登记名称、城市、运营商、家庭/机房类型。复制 `--probe-id` 一键命令在获授权的 Linux systemd 设备执行。城市、运营商是管理员声明；公共来源的声明来自测量服务。
5. NAT 家庭测量点可以主动连接 VPS 做双向 iperf3；VPS 独立追踪家庭回程仍需家庭端可达公网目标。Windows/Mac 没有 Linux 时，可先用公共去程、VPS 回程和公开测速端点；一台家庭设备不能提供其他运营商的真实样本。
6. 另选 **BGP 与 RPKI** 预设，使用登记的 VPS 公网 IPv4/IPv6 自动查最长匹配前缀，从 RIS 和 RouteViews 保存 AS_PATH、观测时刻、collector/peer 与 RPKI。默认六小时；同前缀缓存 55 分钟，API 所覆盖范围和截断会明确标注。图中每条边均有原始路径证据；可缩放、拖动、全屏或用下方路径列表。

回程 = VPS→大陆，去程 = 大陆→VPS。同轮、同一固定测量点、同协议/地址族的报告才配对；公共探针独立展示。中间跳未响应常见于回包限速，不能等同业务丢包；未响应延迟显示 `—`。AS4809 只能支持“观察到 CN2”，不能单独认证 GIA。BGP 是控制平面快照，AS 邻接不能证明商业付费上游或物理直连；未核实 Tier 1 身份时不贴该标签。

## 四、测速：先选择可用资源，再启用全速

1. **国际单连接测速** 已提供覆盖十个国际城市的 19 个 Leaseweb 公布 iperf3 候选；默认仅勾选香港，可搜索添加东京、新加坡、悉尼、洛杉矶、旧金山、纽约、法兰克福、伦敦、阿姆斯特丹。共享节点可能繁忙，Aster 对同一端口做资源预约，繁忙且尚未传输数据时退避最多两次。
2. **大陆单连接测速** 为北京/上海/广州 × 电信/联通/移动九个固定报告位置。选集中登记的授权 HTTP/iperf3 端点，或匹配地区/运营商的已登记测量点；未配置的行会明确说明原因，不显示 0 Mbps。软件无法凭空提供九个不限速测量资源。
3. 第一步设置有效时长 5–20 秒、预热 0/2 秒。默认 **P1 单连接**；iperf3 可另加 P4 或 P8，各自独立展示。HTTP 固定 HTTP/1.1 单数据连接，不能选择多连接组合。
4. 勾选全速流量说明；第二步设独立的低频计划。第三步预览整台 VPS 所有方案累计采集/流量量级，再保存。一个 1 Gbit/s 端点双向各十秒约 2.5 GB，预热和协议开销另计；实际速度更高时流量相应增加。
5. 报告「下行」=流入 VPS，「上行」=流出 VPS。均值使用接收端应用字节/实际秒数；最大值仅取完整一秒区间。iperf3 正向曲线从服务端接收输出获取，反向从客户端接收输出获取。没有服务端逐秒 JSON 时保留均值且注明曲线不可用，不以发送曲线替代。
6. TCP RTT 来自本次数据 socket 的 TCP_INFO/iperf3 sender mean_rtt；重传取相应发送端，远端没有证据时 `—`。工具、实际 IP、连接数、时长、预热、拥塞控制、负载与流量在详情 JSON 中保留，不使用整机 nstat 或独立 Ping 冒充数据连接指标。

Aster 不设置 `iperf3 -b` 或 HTTP 流量速率上限；测到的是两端、路径、CPU/拥塞控制与当前负载共同限制下的实际吞吐，无法保证等于套餐标称端口。公开服务器没有无限共享容量，使用条件仍需遵守。

### 集中资源仅登记一次

打开 **定时计划 → 测量资源**，填名称、地区/运营商、域名/IP、协议/端口、地址族、官方/授权链接及使用条件。保存后可在所有 VPS 的方案中勾选。TCP 延迟资源可归入「国际 · 网站」或「IDC 接入」分类，旧自定义网站迁移后也能继续编辑。HTTP 下载路径必须是明确的测试文件；上传只有端点提供 Aster 接收端报告协议时才启用，普通 PUT/上传网页不能冒充已确认接收字节。密钥存于插件私有状态，不进入目录、报告或分享。

公开目录依据：

- [Leaseweb 官方测速文档](https://kb.leaseweb.com/kb/network/network-link-speeds/)明确发布测试文件及 iperf3 端口 5201–5210，共享端口一次一个会话；目录固定使用 5201，不静默切换节点或地址。
- [xTom 官方 Looking Glass](https://xtom.com/looking-glass/)发布 23 个访问目标；此处只采集这些入口的接入延迟，可能由代理/CDN接入，不能冒称机房内部 RTT。
- [TcpQuality](https://github.com/ibsgss/TcpQuality) 的远端大陆 TOS 目录可以作为候选调查来源；尚未取得其定时批量上传/清理接口用途的明确授权，因此新版不自动启用 PUT/DELETE，也不宣称内置免费九格已全覆盖。原有 TcpQuality 图片诊断仍可读取/运行。

### 可选：自有 HTTPS 接收器

已有可用证书的授权端点上，先运行同一个安装命令，然后：

```sh
sudo python3 /usr/local/libexec/aster-network-observatory/http_receiver.py --configure
```

向导读取证书完整链和私钥路径，默认端口 8443，复制证书并创建低权限 systemd 服务，只显示一次密钥。在防火墙放行该端口；集中资源填真实证书域名、HTTP、HTTPS、该端口、下载 `/download`、上传 `/upload` 和密钥。接收器一次一个测速会话、每请求有时限，不把数据写磁盘。证书续期后重跑向导并 `sudo systemctl restart aster-network-observatory-http`；重新配置生成的新密钥也需在集中资源更新。

Linux TCP_INFO 可提供 socket RTT；HTTP 下载的远端发送重传默认不可用。上传报告必须符合接收器协议（HTTPS 验证与 Bearer 授权），不会把客户端送出的字节当成远端已接收。HTTP 下载/上传两方向依次执行，没有带宽限速。

## 五、迁移、历史与分享

- **旧版集中方案 → 批量选择 → 预览迁移**：先展示所有所选方案的范围、口径变化、覆盖和累计容量；确认迁移后原触发器停用，新建新版方案。旧速度多连接不会更名为 P1；旧报告继续在「旧版单次检测与历史」中读取。更早的工具诊断 v1 计划仍独立保留，高流量重复项需在旧计划区暂停。
- 模块各自选择历史轮次，默认最近完整轮；进行中的轮次另有进度入口。重叠的同 VPS/来源/端点/口径/同触发窗口任务共享一次实际测量，并标明共享任务 ID，不忽略另一个方案中新加的目标。
- 原始明细七天，逐目标统计与轮次汇总九十天。50 台 VPS 各 150 个目标、每半小时一轮会产生约 36 万份目标记录/天；应为面板预留磁盘和 inode，先用较小预设观察实际数据目录增长，再扩大范围。过期明细不由均值补造色块或曲线。每轮独立文件与小型日期索引，回传幂等，runner 的私有 outbox 断线后重传既有结果，不会因回传失败重跑测速。
- 每模块「⋯」提供完整 JSON、汇总 PNG、公开分享。PNG 是摘要，逐跳/逐秒证据保存在 JSON。公开分享可被持有链接的人读取，包含 IP/目标/路径，最长七天且不超过明细保留期；可撤销本轮所有分享。静态报告无脚本，可浏览器打印为 PDF。密钥、系统凭证和原生队列不会进入分享。

## 六、排障与验收边界

```sh
sudo systemctl status aster-network-observatory-agent --no-pager -l
sudo journalctl -u aster-network-observatory-agent --since '40 minutes ago' --no-pager
```

- 缺少新版能力：更新插件和 runner；旧 runner 不领取新版操作。缺少 mtr/iperf3 等依赖可重新执行一键命令。
- 长时间排队：查看正在测速的资源和覆盖原因；可以取消整轮，心跳取消采集并清理临时监听。新版轻量任务每 worker 最多四个，吞吐按 VPS/端点预留；公共额度或第三方故障会显示实际原因。
- 无 ASN：私网与不响应跳没有可推断公网 ASN；公共跳补查失败会保留来源错误。取得线路证据后仅展示可解释的观察特征。
- 无大陆九格：需要实际获授权的资源覆盖。Windows/Mac、没有公网地址本身不阻止国际测试；它们也不能自动生成三家运营商的测量网络。
- 日志中的旧记录：Komari 保留历史插件日志，升级不等于清空。以升级时间之后的新记录判断；不要删除插件数据目录来解决缺文件问题。

验证记录见 [实施与验收记录](network-report-implementation-status.md)。真实大陆三运营商资源/生产面板没有提供访问权限，Linux本地实验室、API 合同、浏览器夹具和规模测试不构成三地三网实测覆盖证明。
