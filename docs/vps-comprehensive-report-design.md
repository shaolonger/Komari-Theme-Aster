# VPS 全面报告设计

状态：已在 Aster 1.9.0 实现。本文保留最初基于 Aster 1.8.0 的设计与数据口径；实际操作和限制见[使用指南](vps-report-guide.md)。早期视觉原型和文档截图使用演示数据。

## 1. 产品方案

在 VPS 详情页右上角加入「生成报告」。用户选择日期范围后，一键汇总**该范围内、当前权限可读取的全部监控与检测数据**，形成可阅读、可追溯、可完整离线保存的 VPS 档案。

默认包含全部章节；无需挑指标、逐张截图或手动拼接网络检测报告。先给结论，再给趋势和证据。未支持、未采集、过期、权限不足和请求失败均明确展示，不用 0 或“正常”填补。

主下载格式为**自包含 HTML**：同一套报告排版、图表、章节导航和明细，断网后用浏览器打开即可回顾。PDF 是独立的打印补充格式；JSON 提供本次使用的数据与口径，不能用 JSON 或长截图替代原格式。

## 2. 入口和生成流程

### 详情页入口

- 放在 `Instance.tsx` 顶部的节点切换器旁，按钮使用 `FileChartColumn` 图标与「生成报告」；窄屏保留文字并换行。
- 点击打开日期设置对话框。普通诊断图表的时间范围保持独立；如果用户正查看自定义范围，提供「沿用当前图表范围」，不静默套用。
- 日期默认「最近 7 天」，提供「最近 24 小时 / 最近 7 天 / 最近 30 天 / 本月 / 自定义」。快捷范围是选择便利，不代表后端一定保存了这些日期。
- 表单只有日期、时区和主按钮是常驻项。「与前一等长区间比较」「导出时显示完整 IP」放入可选项；默认关闭，避免额外请求与敏感数据扩散。

### 时间定义

- 跟随主题 `displayTimeZone`，始终显示 IANA 时区与起止时间，生成后冻结。
- 按自然日选择时，结束日期包含当天，内部转换为下个自然日零点的半开区间 `[start, end)`，跨夏令时按当地自然日计算，不能硬加 24 小时。
- “最近 N 天”为生成前 N×24 小时；“本月”为当地月初至生成时刻。允许分钟级自定义；结束时间不能晚于冻结的生成截止时刻。
- 禁止反向、空区间和未来区间。早于数据保留期时展示「所选范围 / 预计可用范围」并允许生成部分报告，不悄悄改日期。
- 负载、Ping、网络报告分别展示预计保留范围；配置为 0、缺省或不可读时按现有后端语义解析，未知就写“需查询确认”，不据此虚构最早日期。

### 一键生成

1. 点击「生成全面报告」时冻结节点、区间、时区、权限上下文与截止时刻。
2. 读取能力与元数据，分组拉取资源、流量、Ping、历史网络检测及可选比较区间。
3. 展示「正在收集 · 已完成 3/6 类数据」等真实阶段，提供取消。只有总量已知才显示百分比。
4. 计算统计、覆盖率、结论及关联事件，再打开专用报告阅读页。
5. 完整或部分成功都可以下载；部分成功在页首列出具体缺项与影响。全部失败则保留日期和错误，允许重试。

建议路由为 `/instance/:uuid/report`，入口按需加载。URL 可保存日期和时区，不包含报告正文或私有信息。浏览器刷新后显示“重新生成此范围”，不会声称正在恢复原报告；原报告以下载文件为准。

## 3. 阅读结构与视觉

继承 Aster 的中性灰底、轻描边、圆角、蓝色强调和已有 CPU / 内存 / 流量颜色。减少装饰色和大面积渐变。主内容宽度约 1120px，桌面左侧章节导航、右侧报告正文；小屏改为顶部章节选择器，单列排版。

页面顶部固定显示节点名称、范围、时区、生成时间、报告状态及「下载原格式」；原型的固定内容指文档结构，正式实现仅在宽屏使用不遮挡正文的 sticky 工具栏。

报告采用章节阅读：概览默认打开，导航切换章节；下载 HTML 保留相同交互，PDF 将全部章节按顺序展开。章节内遵循「一句发现 → 核心统计 → 图表 → 证据明细」。图表不默认平滑，不跨缺测连接；单位、方向、时区、采样精度直接可见。核心数字使用等宽数字，颜色始终配文字。

| 章节 | 覆盖内容 | 推荐图表与排版 |
| --- | --- | --- |
| 报告概览 | 资源使用特征、主要风险、数据覆盖、区间对比、缺项 | 4 个关键数字、3 条带证据的发现、CPU/内存趋势、Ping 小图、数据可用性条 |
| 性能与资源 | CPU 型号/核心、CPU 使用、内存、Swap、负载、磁盘占用、进程、TCP/UDP 连接；GPU/温度按能力 | CPU/内存分图或同尺度百分比图；磁盘起止变化；统计表列均值、峰值、P95及其精度；连接与进程独立小图 |
| 网络质量 | 全部可见 Ping 任务、时延/丢包、路由、三网测速、国际连通/测速、IDC、BGP/RPKI、已有 HTTPS 检测 | Ping 趋势与任务表；按地区×运营商的检测矩阵；分上下行测速分布；选定轮次的逐跳表、AS 路径和 RPKI 状态 |
| 带宽与流量 | VPS 视角上/下行速率、峰值、期间流量、累计计数器覆盖、当前套餐配额 | 双向带宽趋势、每日上下行堆叠柱、期间流量与当前计费周期额度并列且明确区分 |
| 运行与稳定性 | 监控覆盖时间、缺测段、当前在线状态/uptime快照、持续高负载段、已证实的重启/离线事件 | 数据覆盖时间带、按天覆盖率、事件表；缺少历史在线事件时不显示历史在线率或 SLA |
| 配置与资产 | 厂商/地区/用途/标签、架构/虚拟化、OS/内核/Agent、IP、硬件容量、续费、币种、周期、到期、自动续费、公开备注 | 配置清单与容量条；价格/到期卡；统一标注“生成时快照”，未知项保留 |
| 事件与建议 | 资源超阈值、Ping 丢包、网络检测失败、流量重置、缺测等可证据化线索 | 时间线 + 严重性文字 + 指标/任务/时间/持续长度 + 建议；能够跳转到对应章节与证据 |
| 数据与口径 | 查询及实际覆盖范围、后端/采样/聚合/截断状态、字段可用性、规则与阈值、导出版本 | 数据质量表、术语说明、来源/轮次 ID、可展开的本次输入明细 |

未采集的 IO 读写、IOPS、SMART、文件系统分区、每进程资源、容器、应用日志、漏洞/安全扫描等，只能在能力清单中显示“当前数据源未提供”；不能声称仅凭 Komari 指标即可全面审计这些方面。

图表提供悬浮/点击值、图例开关与可访问数据表。矩阵不把失败和未测画成同一种颜色。零值是有效观测，缺测使用空缺与说明。表格仅在列数无法收缩时局部横向滚动。

## 4. 数据来源与当前接入边界

| 来源 | 当前可复用 | 需要为报告补足的能力 |
| --- | --- | --- |
| `useNode` / `InstanceDetails` / `nodeMetaOverlay` | 节点、实时状态、登录后元数据补齐与标签覆盖 | 冻结快照及字段来源；标记实时/配置与历史差异；只读取用户当前已授权的数据 |
| `getLoadRecords` / 官方 `public:queryMetrics` / fork `common:getRecords` | CPU/内存/Swap/负载/磁盘、带宽/累计流量、连接与进程序列；自定义日期 RPC | 严格日期验证、字段存在性、原始/聚合精度、覆盖范围、截断与缺测元数据；报告专用取消信号 |
| `getPingRecords` / `getComparisonPingRecords` / 官方 Ping 统计 | 多任务时间序列及 `sample_count` / `loss_count` | 按任务保留权重和粒度；当前任务目录不保证包含已删除任务，历史未知 ID 保留为“历史任务 #ID” |
| `trafficRange.ts` | 计数器差分及 `measured / partial / unavailable` 语义 | 缺字段不能先归零；边界样本、计数器重置和跨缺测区间需更严格标识；`measured` 不自动等同精确自然日账单 |
| `reportObservatory.ts` | 六类网络报告能力、历史轮次分页与轮次明细 | 当前列表仅 module/cursor，无日期参数；先完整分页并过滤，规模大时补服务端只读 `from/to` 查询与分页完整性标志 |
| `nativeObservatory.ts` / 旧网络历史 | 原有 HTTPS、路径/测速等观测与摘要 | 按记录 ID/来源/时间去重；明确新旧数据的采样差异与明细保留期，不把二者当成独立重复测量 |

特别注意：

1. `LoadRecordSchema` 的多项缺失字段默认补 0；官方适配也会归一化。报告必须在归一化前保留字段存在性与质量，或者增加报告专用适配，不能事后根据 0 猜测是否未采集。
2. `getLoadRecords` 的旧 HTTP 回退只接收 `hours`，没有任意起止时间。报告严格模式禁止静默用“最近 N 小时”替代用户选择的旧日期。精确日期能力不可用时，该模块报错/不可用，其他模块仍可生成。
3. 当前模型没有通用、可证明完整的历史在线与重启事件。监控缺样可能来自网络、服务端、采集配置或节点离线，不能据此断言停机。
4. 历史内存/磁盘容量可能借用当前元数据分母；报告显示“按生成时容量换算”，不能将扩容前后的比例冒充历史真实使用率。
5. GPU 和温度在宽松 schema 中存在，不代表后端确实提供；应按原始字段/能力决定。硬件无 Swap 与 Swap 未采集也应分别显示。
6. 报告只汇总既有网络测量，不触发新的测速或探测。区间外“最近一次检测”不能混入区间统计；如用户明确查看它，需作为单独的区间外参考。

## 5. 计算与结论口径

- **缺失与质量**：每个统计值保留 `value | null`、单位、来源、实际范围、样本数、聚合精度和质量原因；“不支持 / 未采集 / 已过期 / 无权限 / 查询失败 / 已截断”分别记录。报告完整状态只表示各项已正确处理，不能表示所有指标都有数据。
- **均值**：连续资源优先按有效观测时长加权，权重最多延伸到配置的最大可信间隔，超过的间隔是未知；聚合桶使用其时间权重。Ping 按成功探测样本数加权。只有点值且采样不规则时，若无法合理恢复权重，明确标为“采样均值”。
- **分位数与峰值**：有原始样本才展示原始 P95；只有桶均值时可展示“桶均值 P95 / 桶均值峰值”，不能称为原始峰值或原始 P95。后端能返回真实 min/max/count 的桶则保留它们。不同指标可有不同粒度。
- **丢包**：`总 loss_count / 总 sample_count`；无权重的原始探测按真实次数统计。失败探测不进入成功时延分布；不能把超时视为 0ms，也不能平均各桶丢包百分比。
- **抖动**：原始成功连续样本可按已声明的相邻差或标准差公式计算；聚合数据不足以恢复时展示“不可计算”，不从桶均值伪造。
- **超阈值**：展示规则名、阈值、时长、粒度和断点规则。默认资源提示可设 CPU >80%、内存/磁盘 >85%，持续至少 10 分钟；值写入规则快照。只有桶均值时表述为“连续桶均值超过阈值”，真实尖峰不可知。网络阈值按任务/场景定义，缺少基线时只描述观测，不武断判定线路优劣。
- **期间流量**：相邻累计计数器差分，VPS 视角上/下行分别计算。边界不精确、采样缺口、重启/计数器重置、来源变化均使质量下降；记录已知量/估算范围，不能简单 `max-min`，也不将当前周期用量当成所选期间用量。现有函数支持重置后的累加但会标记 partial，正式实现应进一步说明可能遗漏量。
- **可用性**：监控覆盖率 = 可证明有效的采集时间 / 所选时间；不等于服务在线率。只有可靠在线状态/事件源覆盖该区间，才新增“监测到的在线率”，并单列未知时段与算法。当前 uptime 是生成时快照。
- **对比区间**：可选项，默认关闭。前一等长区间使用相同指标和计算规则；保留双方覆盖和精度，明显不可比时不画增减箭头。前值 0 时使用绝对变化或“此前为 0”，不生成无穷大百分比。
- **网络检测**：按测量时间归档，轮次部分跨界时只纳入区间内已完成的测量并标注“部分轮次”。规划时间/完成时间分别保留；超时/失败结果保留失败状态。探测协议、目标、地址族、方向、来源、配置指纹、单/多连接和测量方法不同的结果不混算；中间路由跳点丢包不直接等于端到端丢包。
- **资产成本**：当前续费金额/周期/到期时间是配置快照。可选的期间折算费用仅为“按当前套餐估算”，不能标作实际账单。多币种不默认相加，换算只用明确快照的汇率及时间。
- **结论生成**：首版采用可复现的本地规则模板，每条发现包含指标、日期、数值、阈值和证据引用；建议使用“建议检查”等措辞，相关变化不能直接写成故障根因。不依赖外部 AI 服务，不编造综合健康评分。

## 6. 下载与长期回顾

### 主格式：离线 HTML

下载名示例：`Aster-东京Core-20261012_20261018-report.html`；文件名清理控制字符与路径分隔符，重名加报告 ID 短码。内容包括：

- 全部章节的渲染结果、全部已纳入的数据与统计、规则快照、版本、报告 ID、生成时间、区间与时区。
- 内联 CSS、SVG 图表与少量自包含脚本；字体使用本地系统字体，图标使用随报告封装的资源，不引用 CDN、原站图片、远程字体、模块导入或 API。
- 保留章节导航、图例开关、明细展开、图表触摸/键盘可用的数据表及主题快照。布局允许随屏幕宽度重排，“原格式”指同样内容、样式和交互，不承诺跨设备字体像素完全一致。
- 默认固化生成时的外观，离线文件不会因原站升级、退出登录或数据过期而变化。不自动刷新、不补测、不上传任何数据。
- 内置打印样式，打印时展开全部章节和关键表格，隐藏操作按钮，重复表头，避免拆开短图表与标题。

**导出必须从冻结的 `ReportModel` 渲染，不能从当前 DOM 截图/复制**，否则已隐藏章节和未打开的明细可能丢失。HTML 导出器和在线阅读器共享图表与排版组件，下载前等待所有图表就绪并验证没有外链资源。

### 补充格式

- 「打印 / 存为 PDF」调用浏览器打印并提示另存 PDF，保留文本检索与矢量图；不能声称已直接生成 PDF。自动下载 PDF 如有需求，可后续接独立渲染器。
- 「下载数据 JSON」包含本报告实际使用的输入与派生值、精度、截断和缺失状态。聚合输入不能命名为“全部原始数据”。
- 导出脱敏默认与在线预览一致；开启完整 IP 后，在线预览和下载同时显式标识。脱敏发生在构造导出模型前，覆盖正文、SVG、隐藏明细、IP/目标/路由地址和 JSON，不能只遮住可见文字。令牌、Cookie、探测器凭证、私有备注和未经当前用户授权的字段永不进入报告。
- 本地回顾只依赖下载文件，首版不承诺服务器永久保存或账号间同步。文件可分享给他人，但分享是用户自行传递文件，不自动生成公共链接。

## 7. 实现拆分建议

```text
src/components/instance/report/
  ReportEntry.tsx             # 详情页按钮与日期对话框
  ReportProgress.tsx          # 分阶段进度、取消、部分失败
  ReportReader.tsx            # 共享导航与阅读布局
  sections/                  # 八个章节，消费冻结模型
  ReportChart.tsx             # 在线/离线共用 SVG 图表与数据表
src/pages/InstanceReport.tsx  # lazy route
src/services/instanceReport.ts
  # 只读严格日期查询、能力/权限、分组收集、取消和质量元数据
src/utils/instanceReport/
  model.ts                   # 不依赖 React 的带版本报告模型
  aggregate.ts               # 统计、覆盖、流量、对比
  findings.ts                # 可解释规则与证据引用
  redact.ts                  # 在序列化前构建安全报告投影
  exportHtml.ts              # 内联资源、静态全章节、离线导航
src/workers/instanceReport.worker.ts
src/styles/instance-report.css
```

模型至少包括 `schemaVersion / reportId / generatedAt / cutoff / nodeSnapshot / requestedRange / timeZone / sources / sections / findings / rules / privacy / exportTheme`。每个 source/metric 包含 `availability / observedRange / expectedInterval / sampleCount / aggregation / truncation / warnings`。状态展示将“请求成功”与“历史覆盖充分”分开。

查询结果先归档为不可变输入，聚合在 Worker 内执行。图表使用适量显示点（每系列约 600–1200 个），保留极值与缺口；统计用全部已取得的有效输入，不用抽稀后的图形数据反算。现有 uPlot 可继续服务诊断页；报告用可序列化 SVG，避免 Canvas 仅留截图。

独立数据源初始并发上限 3；网络轮次明细并发上限 3，可逐步调优。分段查询按半开时间边界去重，不能将两端重复样本计两次。到达上限时降低图表分辨率但不暗中缩减统计范围；后端只提供聚合数据时保存精度标记。无法完整分页或达到内存预算时，显式部分报告/用户选择缩小范围，不能导出“完整”状态。

首版建议按报告输入 32MiB、单文件 HTML 20MiB 设置初始保护阈值，通过浏览器实测再调整；阈值是设计起点，不是当前已有性能保证。超大任务在取数前显示估计，取数中持续检查；不在现有首页包中引入导出/图表依赖。

取消通过 AbortController 贯穿服务层与 Worker，并在页面切换/节点切换时取消。独立模块失败可按原冻结范围重试；如果重新取数会影响已生成结论，创建新的报告修订并统一重算，不能把不同截止时刻的数据拼在一起。

导出 HTML 将节点名/标签/备注等视为文本，不插入不可信 HTML；JSON 脚本块转义 `<` 和结束标签等边界，离线内容使用限制联网的 CSP。授权失败保持原错误语义，不通过其他接口绕过权限。

## 8. 状态与边界体验

| 状态 | 用户看到的结果 |
| --- | --- |
| 范围超出保留期 | 仍显示原选日期、实际覆盖、缺失原因；生成部分报告 |
| 仅部分指标可用 | 已有章节正常阅读；缺项留位置与原因，不展示虚构数值 |
| 无网络插件/未配置任务 | “未启用网络检测 / 未配置 Ping”；计为未采集，不影响资源报告 |
| 网络明细已过期 | 只展示真实保留的轮次摘要，禁用已不存在的逐跳证据；不恢复/补造明细 |
| 接口拒绝访问 | 对应章节显示无权限；其他已授权模块正常；不把整份报告当登录入口 |
| 任意旧日期仅能使用 hours 回退 | 该模块提示“当前数据源无法精确查询此日期”，不换成最近窗口 |
| 整段无数据 | 展示范围、配置快照和来源状态，可下载“无历史数据报告”，不生成趋势和健康结论 |
| 取消/断网/导出失败 | 保留已选日期；已生成的报告可继续阅读；错误明确且可重试 |
| 当前节点已经离线 | 仍可生成其被保留的历史；当前离线状态只作为快照 |

## 9. 交付顺序

首版完整交付入口、严格范围收集、八章节、规则摘要、自包含 HTML 与打印。网络章节复用已有检测结果，不要求部署新的采集系统。缺失的历史在线/安全/IO 数据以能力说明交代。

后续仅在真实需要下补服务端日期索引/更长摘要保留、可靠在线事件、容量历史、报告存档列表和直接生成 PDF；这些不能成为首版下载能力的前置依赖。

## 10. 验收清单

1. 官方与 fork 两条路径对同一精确日期生成报告；仅 hours 回退不能改变范围。
2. 原始样本/聚合桶、缺字段/真实 0、无 Swap/未采集、未知/离线均能正确区分。
3. 不规则采样、DST、边界重复、计数器重置、Ping 加权丢包、分位数精度、不同容量分母和前值 0 的对比均有有意义的单元验证。
4. 网络历史多页完整检索，部分轮次/过期详情/不同方法与方向不混算；不触发任何探测或测速。
5. 下载 HTML 后断网打开，全部章节/图表/数据表/隐藏明细可用；没有外部资源或 API 请求；与在线报告同一 reportId、数值、来源与主题。
6. 在线与离线均检查 1440px、1024px、390px、320px、深浅色与键盘阅读；PDF 无标题孤行、图表裁切、遗漏章节或横向溢出。
7. 脱敏后的 HTML/JSON 源码中不存在被遮蔽的完整 IP、私有目标和凭证；节点名/备注中的 HTML 与脚本结束标签不被执行。
8. 三十天高密度数据与多轮网络明细下检查内存、取消和重试；无关详情页/首页不为报告加载新增大包。

## 11. 本次设计产物

本设计文档描述功能与验收口径。v1.9.0 已实现独立日期设置页、严格范围收集、八章节阅读、本地统计、默认脱敏、自包含 HTML 与打印。网络检测使用模块表格和可展开的 MTR、测速、HTTPS、AS 路径/RPKI 证据；大规模采样点保留在内置 JSON 中。阅读器与下载文件共用同一模型和渲染器，打印时展开全部章节及关键证据。

早期交互稿只演示设计；仓库的 `docs/images/current/vps-report-*.png` 由实际构建产物和兼容模拟后端在浏览器中截图。报告专项门禁已覆盖两条后端、30 天查询、离线阅读、手机宽度、深浅主题和 PDF，发布仍须通过完整门禁。
