## 插件启动报 wildcard 冲突

插件 1.9.0 把旧凭证路由的参数名从 `:uuid` 改成了 `:id`。Komari 卸载插件后保留 Gin 路由槽，同一进程中覆盖升级会出现 `conflicts with existing wildcard`。插件 **1.9.1** 保留原来的参数名，并可复用全新安装 1.9.0 时留下的 `:id` 路由槽。

覆盖上传 `Aster-Network-Observatory-v1.9.1.zip`，然后重新启用插件；若出现权限提示，批准原有权限即可。**无需删除插件数据、重置凭证、重装 VPS 探测器或更换现有 1.12.0 主题。** 修复同时覆盖全新安装、从 1.8.0 升级、从全新安装的 1.9.0 升级和反复启停。

## 安装与升级

**泰尔超时与恢复（1.18.0）**：更新插件 **1.15.0** 后，旧探测器的目录超时也可在无测速载荷时有限退避；公共测速继续全局串行，每项结束后增加短冷却。为应用分阶段超时、目录短缓存、候选切换与仅补失败方向，需要将相关 VPS 的探测器保留凭证升级至 **1.12.0**。已成功方向不重复测量，有载荷的失败不自动重跑，重试共用原流量预算。无须重置凭证或重建计划；不开启 IPv4 替代 IPv6。具体计时、重试次数与备用目录限制见[可靠性说明](../docs/network-native-measurements.md#公共测速可靠性与诊断1180)。

**LXC 安装诊断（1.17.1）**：安装器在创建子进程前，用内置命令读取容器 / 可见父级的进程与线程配额；不足时直接显示实际 `pids.current` / `pids.max`，避免只剩 `can't fork` 和 curl 写入失败。正常安装的探测器仍为 **1.11.0**，无需升级或重置凭证；本次也不要求已更新至 1.17.0 / 1.14.0 的面板为此再更新。资源配额需由宿主机或服务商调整，见下方 LXC 排障。

**小时 CPU 尖峰优化（1.17.0）**：优先更新面板插件 **1.14.0** 和主题 **1.17.0**。历史保留期改为到期索引与分片维护，计划按成员分批派发；活跃队列改为 64 桶原子分片和写前事务，领取 / 结果不再重写整份队列。旧内联队列自动迁移，凭证、原计划时间和报告保留；探测器 **1.11.0** 的测速 / 结果重试优化可使用现有保留凭证升级命令应用，旧探测器仍能通信。首次旧数据迁移可能持续数分钟至更久，后台有预算推进。性能数字、迁移边界及核验见 [CPU 排查与修复](../docs/network-observatory-cpu.md)。

**卡片精简展示（1.16.0）**：同时更新主题 **1.16.0** 和插件 **1.13.0**。默认每格显示一个优选线路标签，并隐藏线路确认与测速计量说明；工作室的对应面板可分别开启。IPv4 / IPv6、测试时间和点击查看完整证据继续保留，已有探测器与凭证无需变更。详见[排序与配置](../docs/network-card-presentation.md)。

**双栈切换与卡片时间（1.15.1）**：同时更新主题 **1.15.1** 和插件 **1.12.1**。三网测速可切换 IPv4 / IPv6，各族保留自己的最新轮次、结果与时间；线路也显示当前地址族的最近测试时间。卡片去掉发布 / 管理提示，设置继续统一在工作室。已有单族快照保留，另一族从历史汇总分批恢复，完成后记住恢复状态，避免重启重复扫描；公开读取不扫描历史。探测器仍为 **1.10.0**，无需重装或重置凭证。

**主页三网测速（1.15.0）**：同时更新主题 **1.15.0** 和插件 **1.12.0**，探测器仍为 **1.10.0**，无需重装或重置凭证。卡片展示最新发起且已结束的大陆测速轮次，三网 P1 上下行、城市切换、实际 IPv4/IPv6 及结束时间；失败与缺测保留本轮状态。受控与泰尔公共测速均支持，P4/P8 不替代 P1。点击数值查看各项测量时间与计量方式。摘要超过 24 小时提示时效；不会把不同轮次、城市和地址族拼接为同一结果。

**Komari CPU 升高修复（1.14.1）**：面板插件 **1.11.1** 缓存解析后的状态、按测量端索引任务，空闲轮询不写盘、心跳合并写入，减少重复调度及历史清理。只需覆盖更新面板插件；已有探测器仍为 **1.10.0**，无需重装或重置密钥。详见[排查与验证步骤](../docs/network-observatory-cpu.md)。

1. 从[最新 Release](https://github.com/shaolonger/Komari-Theme-Aster/releases/latest) 下载主题和插件 ZIP，在 Komari 分别上传更新。批准插件 API 路由与读取节点清单的系统 RPC 权限。插件只调用 `admin:listClients`，不调用远程命令接口。
2. 在「探测器与测量点」选 VPS，生成凭证，复制安装命令到 VPS 运行，在隐藏提示中粘贴密钥。已有相同面板 / UUID 的密钥可在升级向导中回车保留。
3. 需要本次路由元数据采集修复的 VPS 执行一键升级，确认探测器显示 **1.9.1**。旧探测器原有检测继续可用，更新面板插件不会重置凭证：

   ```sh
   curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh | sudo sh
   ```

安装器支持 systemd（Debian / Ubuntu、RHEL 系、openSUSE）和 OpenRC（含 Alpine 3.21），使用 apk 的 Alpine 不再要求 systemctl。安装包先验证 SHA-256。大陆测量点使用独立 `--probe-id`、凭证文件和服务，可与本机 VPS 探测器共存。

`--profile auto` 为默认值：物理内存 / 容器内存上限不超过 192 MiB，或根分区可用空间少于 192 MiB 时，使用 `lite`；其余使用 `full`。128 MiB / 256 MiB 的 Alpine VPS 建议显式使用 `--profile lite`。轻量模式仅安装 Python、CA 证书、MTR 和支持 TCP 的 traceroute，延迟采样并发降为 1，跳过 NextTrace、iperf3、openssl 命令和 nping 的自动安装。基础 TCP 延迟、连接质量、MTR 路由仍可用；缺少 NextTrace 时不会采集其位置、WHOIS 等补充信息，自建 iperf3 测速、认证双向测速及原始 SYN 比较需要对应工具。已有工具不会被卸载。完整模式可用 `--profile full` 补齐工具，并校验固定版本 NextTrace；不建议在此规格上运行多个重负载检测。

```sh
curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh | sudo sh -s -- --profile lite --server-url 'https://你的面板地址' --node-uuid '你的节点UUID'
```

Alpine 以 root 登录时可省略 `sudo`。升级同面板、同节点时在密钥提示处回车保留原凭证，无需重新生成。OpenRC 节点服务名为 `aster-network-observatory`，大陆测量点为 `aster-network-observatory-probe-<UUID>`；用 `rc-service <服务名> status/restart/stop` 管理，凭证验证成功后加入 default 运行级。日志交给系统 syslog，停止时取消正在执行的测量子进程。可选 HTTP 测速接收器不会随安装自动开启。

**本版直接移除了旧工具诊断、旧单次报告、旧计划、图片报告、旧调度器与迁移界面。没有兼容与迁移面板。** 新版轮次报告和现有探测器凭证仍可使用；本版不提供旧数据迁移或旧报告浏览。为已安装的 1.7 探测器保留了凭证验证 / 心跳的通信应答，不执行任何旧检测。建议统一升级探测器以停止旧轮询。

### LXC 安装时出现 `can't fork`

`sh: can't fork: Resource temporarily unavailable` 表示 shell 无法创建新进程，优先检查容器或父级的进程 / 线程配额、用户进程限制；不能仅凭 128 MiB 内存就断言是内存不足。若紧接着出现 `curl: (23) Failure writing output to destination`，通常是安装 shell 退出，下载管道随之关闭。cgroup 的 `pids.current` 包含线程，进程列表看起来不多也可能达到 `pids.max`；父级限制同样生效。参见 [Linux 进程控制器说明](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v1/pids.html)。

安装器先用 shell 内置命令读取可见的 cgroup v1 / v2 及父级配额；剩余少于 8 个任务名额时，在安装依赖、下载发布包之前停止并打印实际数值。这是安装前的最低余量检查，并非运行期资源保证；宿主机未暴露的父级配额和其他进程同时消耗名额仍可能导致后续失败。早期身份与内存读取也使用内置命令，减少 `id` / `cat` / `awk` 子进程。

可将以下**整行**复制到容器终端，命令不创建外部进程；`pids.events` 中的 `max` 是历史拒绝计数，非零本身不表示此刻仍然满额。若这里没有可见配额，需由宿主机 / 服务商检查父级限制：

```sh
ulimit -a; for f in /proc/self/cgroup /sys/fs/cgroup/pids.current /sys/fs/cgroup/pids.max /sys/fs/cgroup/pids.events /sys/fs/cgroup/memory.current /sys/fs/cgroup/memory.max /sys/fs/cgroup/memory.events /sys/fs/cgroup/pids/pids.current /sys/fs/cgroup/pids/pids.max; do if [ -r "$f" ]; then printf '\n%s\n' "$f"; while IFS= read -r line; do printf '%s\n' "$line"; done < "$f"; fi; done
```

root 用户可先下载再执行，减少管道和 sudo 的同时占用；**两步分别执行，下载成功后再执行第二步**。它只能减少安装瞬时开销，不能绕过已耗尽的 LXC 配额。需先停止确认不需要的服务，或请宿主机 / 服务商调整限制，不能在容器内盲目修改 `pids.max` 或批量终止进程：

```sh
curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh -o /tmp/aster-network-observatory-install.sh
sh /tmp/aster-network-observatory-install.sh --profile lite --server-url 'https://你的面板地址' --node-uuid '你的节点UUID'
```

Alpine 3.21 的 1 CPU / 128 MiB 安装与服务回归继续单独验证，另加入 `pids.max=1` 的实际容器测试，确保完全无法 fork 时也能输出上述配额诊断。这不代表探测器能在仅有一个任务名额的容器中运行。

## 三网线路

卡片默认显示一个优选观测网络：电信 CN2 ＞ CTGNet ＞ 163，联通 9929 ＞ 10099 ＞ 4837，移动 CMIN2 ＞ CMI ＞ 9808。仅在已观测的名称中选择；这是摘要展示顺序，不是实际带宽 / 延迟排名，也不认证 GIA 产品。工作室 → 网络观测 → 主页三网线路可切换“完整线路”，以 ` + ` 连接全部观测网络；线路确认与差异说明另有独立开关，默认关闭。点击结果始终可查看完整组合、终点确认、城市 / 来源及真实 ASN 序列。缺测与过期独立保留，颜色不代表精品等级。

1. 在「检测方案」选择大陆路由预设，设置执行时间与 VPS，预览覆盖后保存。
2. VPS → 大陆目标是回程；大陆测量点 / Globalping → VPS 是去程。仅安装 VPS 探测器不能凭空获得大陆去程。IPv4 与 IPv6 需要分别配置相应地址族和目标。
3. 管理员首页可直接看到自己的测量摘要，无需向访客公开。访客默认看不到；在「主页三网线路」明确选择可见节点并保存后才发布。
4. 升级首次汇总会从仍保留的新版路由明细重建摘要，也可点击「从报告重建摘要」。无需重装探测器来修复已有报告与卡片脱节的问题。

摘要依据实测 ASN，共用报告的识别规则；目标名“CN2”不构成 CN2 线路证据。不同城市 / 协议保留独立观测，同一天可显示组合结果；双向、双栈不互相补造。缺少覆盖、失败、未识别、部分路径与过期分别表示。超过 24 小时标记过期，超过七天不再显示为当前证据。管理员可从卡片追溯对应轮次。

访客摘要仅包含公开节点的线路标签、ASN、时间、状态和报告标识，不包含目标 IP、原始跳点、测量点身份或凭证。隐藏 / 删除节点在清单刷新后被排除。公网摘要读取使用缓存，不扫描原始报告。

## 测量资源的区别

“目标端点”是被测对象；“大陆测量点”是执行探测的 Linux 设备；“VPS 公网地址”是去程和双向测速的连接目标。它们都是测量基础设施，不是卡片显示开关，因此各有明确面板。国际延迟来自插件的定时 TCP 样本，与首页 Komari Ping 任务独立。

大陆测速需要实际存在且允许所选用途的端点 / 测量点。预览会列出缺少资源的原因，九格缺测不补造 Mbps。全速测速会消耗带宽和流量，需在方案中确认；临时认证监听在任务结束或超时后关闭。

报告操作、各模块测量口径、可选 HTTPS 测速接收器和排障见[详细指南](../docs/network-report-v3-guide.md)。

## 保留凭证升级与可选自动更新（1.14.0）

先更新主题 **1.14.0** 和面板插件 **1.11.0**。在「探测器与测量点」选择 VPS 后，安装 / 升级命令始终可见，复制命令不会调用凭证接口。现有身份使用 `--upgrade --profile preserve`：不再提示输入密钥，不写入已有面板地址、UUID、密钥或安装模式，也不增装工具。旧探测器首次执行时会引导加载新维护程序，随后即可选择自动更新。root 登录省略 sudo。

```sh
curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh | sudo sh -s -- --upgrade --profile preserve --server-url 'https://你的面板地址' --node-uuid '你的节点UUID'
```

大陆测量点使用同一命令，将 `--node-uuid` 换成 `--probe-id`。如果原密钥已经被重置或撤销，需要使用新密钥重新配置；升级不会恢复已失效的凭证。重置和撤销放在独立管理区域，需要确认才会执行，都会中断相应的原凭证授权与测量任务。

“允许自动更新”默认关闭，只能由管理员为已接入的身份开启。安装器会部署独立维护调度器：systemd timer 或 OpenRC 管理的独立 BusyBox cron，每小时检查一次（OpenRC 为每小时第 17 分钟），不增加第二个常驻 Python 进程。新机制需要先在各 VPS 执行一次升级命令；原有旧探测器无法自行安装尚未具备的更新能力。旧面板插件缺少维护接口时自动检查直接退出。

调度器通过原有出站 HTTPS 获取面板指定的兼容固定版本，而非每次追随 GitHub latest。只有安装了新维护程序、明确允许且有更高建议版本时才自动升级。同机 VPS 与大陆测量点共用文件，所有本机身份都允许后才自动更换；建议版本不一致、仍有测量或有管理员停止的服务时等待，不会擅自启动被停止的服务。未升级探测器或关闭自动更新时，面板更新仍保持旧凭证有效。

升级前校验固定 GitHub 发行地址、SHA-256、文件白名单、版本 / 协议及 Python 语法，验证原凭证仍可访问面板。取得各身份的十分钟维护租约后暂停领取新任务，再停止原服务并替换文件。新版必须启动成功、上报新版本且出现新的进程心跳身份，才判定成功，避免旧心跳误报。失败恢复备份文件及原服务；备份与升级锁只保存在本机 root 私有状态目录，不包含密钥配置。意外中断的事务会在下一次维护 / 开机维护中先恢复。systemd 与 OpenRC 都有集成验证。

调整轻量 / 完整模式或补齐工具时，使用普通安装命令及 `--profile lite|full`，在原密钥提示处回车保留。维护升级始终保持现有模式和工具。
