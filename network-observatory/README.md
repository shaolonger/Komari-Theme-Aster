# Aster 网络观测

主题 **1.12.1** / 插件 **1.9.1** / 探测器 **1.8.0**。支持 Komari ≥1.4.3，独立探测器通过出站 HTTPS 领取任务，不需要 Web SSH 或 Agent 远程执行权限。

所有配置统一在 **Aster 工作室 → 网络观测**：

| 面板 | 用途 | 保存方式 |
| --- | --- | --- |
| 主页延迟检测 | Komari Ping 任务、多目标延迟与丢包、顺序及汇总策略 | 页面顶部保存主题设置 |
| 主页三网线路 | 首页显示、管理员预览、访客发布范围、从报告重建摘要 | 面板独立保存，立即生效 |
| 检测方案 | 报告模块、目标、定时、VPS 与分组继承 | 预览覆盖与容量后保存，立即生效 |
| 探测器与测量点 | VPS / 大陆设备凭证、在线状态、能力、公网双栈地址及测速端口 | 凭证与地址操作立即生效 |
| 目标端点 | 内置目录、自定义 HTTP / iperf3 / TCP 目标及授权条件 | 面板独立保存，立即生效 |

入口：`/?view=theme-manage&section=network`。首页快捷入口带上所选 VPS；实例页专注关联方案、当前 VPS 的立即检测和轮次报告，编辑时进入同一个配置中心。`/network-observatory` 也直接进入此中心。

## 插件启动报 wildcard 冲突

插件 1.9.0 把旧凭证路由的参数名从 `:uuid` 改成了 `:id`。Komari 卸载插件后保留 Gin 路由槽，同一进程中覆盖升级会出现 `conflicts with existing wildcard`。插件 **1.9.1** 保留原来的参数名，并可复用全新安装 1.9.0 时留下的 `:id` 路由槽。

覆盖上传 `Aster-Network-Observatory-v1.9.1.zip`，然后重新启用插件；若出现权限提示，批准原有权限即可。**无需删除插件数据、重置凭证、重装 VPS 探测器或更换现有 1.12.0 主题。** 修复同时覆盖全新安装、从 1.8.0 升级、从全新安装的 1.9.0 升级和反复启停。

## 安装与升级

1. 从[最新 Release](https://github.com/shaolonger/Komari-Theme-Aster/releases/latest) 下载主题和插件 ZIP，在 Komari 分别上传更新。批准插件 API 路由与读取节点清单的系统 RPC 权限。插件只调用 `admin:listClients`，不调用远程命令接口。
2. 在「探测器与测量点」选 VPS，生成凭证，复制安装命令到 VPS 运行，在隐藏提示中粘贴密钥。已有相同面板 / UUID 的密钥可在升级向导中回车保留。
3. 每台 VPS 执行一键升级，确认探测器显示 **1.8.0**：

   ```sh
   curl -fsSL https://github.com/shaolonger/Komari-Theme-Aster/releases/latest/download/Aster-Network-Observatory-install.sh | sudo sh
   ```

安装器支持带 systemd 的 Debian / Ubuntu、RHEL 系、openSUSE，校验 ZIP 和固定版本 NextTrace。安装 Python、MTR、traceroute、iperf3 等依赖，不再安装或调用 TcpQuality。大陆测量点使用独立 `--probe-id` 和 systemd 服务，可与本机 VPS 探测器共存。

**本版直接移除了旧工具诊断、旧单次报告、旧计划、图片报告、旧调度器与迁移界面。没有兼容与迁移面板。** 新版轮次报告和现有探测器凭证仍可使用；本版不提供旧数据迁移或旧报告浏览。为已安装的 1.7 探测器保留了凭证验证 / 心跳的通信应答，不执行任何旧检测。建议统一升级探测器以停止旧轮询。

## 三网线路

1. 在「检测方案」选择大陆路由预设，设置执行时间与 VPS，预览覆盖后保存。
2. VPS → 大陆目标是回程；大陆测量点 / Globalping → VPS 是去程。仅安装 VPS 探测器不能凭空获得大陆去程。IPv4 与 IPv6 需要分别配置相应地址族和目标。
3. 管理员首页可直接看到自己的测量摘要，无需向访客公开。访客默认看不到；在「主页三网线路」明确选择可见节点并保存后才发布。
4. 升级首次汇总会从仍保留的新版路由明细重建摘要，也可点击「从报告重建摘要」。无需重装探测器来修复已有报告与卡片脱节的问题。

摘要依据实测 ASN，共用报告的识别规则；目标名“CN2”不构成 CN2 线路证据。不同城市 / 协议保留独立观测，同一天可显示组合结果；双向、双栈不互相补造。缺少覆盖、失败、未识别、部分路径与过期分别表示。超过 24 小时标记过期，超过七天不再显示为当前证据。管理员可从卡片追溯对应轮次。

访客摘要仅包含公开节点的线路标签、ASN、时间、状态和报告标识，不包含目标 IP、原始跳点、测量点身份或凭证。隐藏 / 删除节点在清单刷新后被排除。公网摘要读取使用缓存，不扫描原始报告。

## 测量资源的区别

“目标端点”是被测对象；“大陆测量点”是执行探测的 Linux 设备；“VPS 公网地址”是去程和双向测速的连接目标。它们都是测量基础设施，不是卡片显示开关，因此各有明确面板。国际延迟来自插件的定时 TCP 样本，与首页 Komari Ping 任务独立。

大陆测速需要实际存在且允许所选用途的端点 / 测量点。预览会列出缺少资源的原因，九格缺测不补造 Mbps。全速测速会消耗带宽和流量，需在方案中确认；临时认证监听在任务结束或超时后关闭。

报告操作、各模块测量口径、可选 HTTPS 测速接收器和排障见[详细指南](../docs/network-report-v3-guide.md)。

## 验证

`npm run test:release-gates` 检查单元测试、插件 / 探测器、类型、lint、契约、性能预算与浏览器界面。`npm run test:plugin-runtime` 验证官方 Komari 1.4.3 / 1.5.1 JavaScript 运行环境。测试使用本地 API、工具输出和浏览器夹具，不冒充用户生产 VPS 的三地三网实测。
